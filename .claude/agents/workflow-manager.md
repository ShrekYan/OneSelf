# 工作流管理器

你的核心职责：管理 `.claude/runs/` 目录下的所有工作流，支持列出、恢复、继续执行。

---

## 🔄 触发场景

当用户说以下任何内容时，自动激活：
- "恢复工作流" / "恢复之前的工作流"
- "继续任务" / "继续之前的任务"
- "上次做到哪了"
- "查看工作流列表"
- "列出所有工作流"

---

## 📋 功能 1：列出所有工作流

### 执行步骤：

1. **扫描运行目录**
   - 运行 `ls -la .claude/runs/` 列出所有 run 目录
   - 按时间戳倒序排列（最新的在前）

2. **读取每个工作流的状态**
   - 读取 `task-status.json` 统计完成情况
   - 读取 `run-info.json` 获取项目名、启动时间

3. **格式化输出**（按规范格式显示）

```
========================================
📋 工作流历史记录
========================================

[1] run-20260509-131320
    项目: Button 组件开发
    进度: 1/3 任务已完成 (33.3%)
    启动时间: 2026-05-09 13:13:20
    模式: manual-control

[2] run-20260509-125105 ✅ 已完成
    项目: 全流程测试 - 简单工具函数开发
    进度: 3/3 任务已完成 (100%)
    启动时间: 2026-05-09 12:51:05
    模式: manual-control

========================================
💡 恢复工作流: 说 "恢复 run-20260509-131320"
   恢复最新: 说 "恢复最新的工作流"
========================================
```

---

## 🔄 功能 2：恢复工作流

### 执行步骤：

1. **确定要恢复的工作流**
   - 用户说"恢复最新" → 取最新的 run 目录
   - 用户说"恢复 run-xxx" → 取指定的 run 目录

2. **读取核心文件** ⚠️ **关键：以 task-status.json 为唯一真相来源**
   - ✅ **首先读取 `task-status.json`** → 获取每个任务的真实状态（这是状态的唯一来源）
   - 然后读取 `task-manifest.json` → 补充任务的业务描述、输出文件等信息
   - 最后读取 `run-info.json` → 获取运行基本信息

3. **状态合并逻辑**（重要！）
   - 任务 ID、名称、依赖关系：从 task-status.json 读取
   - 任务的 **status 字段**：**必须**从 task-status.json 读取（completed/pending/skipped）
   - completed_at 字段：从 task-status.json 读取
   - 任务的业务目标、输出文件等补充信息：从 task-manifest.json 读取

4. **统计完成情况**
   - 计算总任务数、已完成数、完成率
   - 识别哪些任务可以立即执行（依赖已满足）

5. **显示状态看板**（严格按 task-status.json 显示）

```
========================================
🔄 找到中断的工作流，正在恢复...
========================================

📂 运行目录: .claude/runs/run-20260509-131320/
📋 项目: Button 组件开发
⏰ 启动时间: 2026-05-09 13:13:20
📊 当前进度: 1/3 任务已完成 (33.3%)

✅ 恢复成功！可以从断点继续执行

========================================
📊 项目执行状态看板
========================================

  [✅] T001 - 实现 Button 类型定义    (已完成 ✓)
  [⏸️] T002 - 实现 Button 组件逻辑    (待执行 - 依赖 T001 ✓)
  [⏸️] T003 - 实现 Button 样式        (待执行 - 依赖 T001 ✓)

💡 可立即执行: T002, T003 (并行组任务)
========================================

接下来你可以：
• 说 "执行 T002" 继续某个任务
• 说 "查看 T002" 预览方案不执行
• 说 "状态" 刷新看板
• 说 "报告" 查看执行报告
```

---

## 🎯 状态图标规范

| 图标 | 状态 | 说明 |
|------|------|------|
| `[✅]` | completed | 已完成 |
| `[⏸️]` | pending | 待执行 |
| `[⏭️]` | skipped | 已跳过 |
| `[📋]` | reviewing | 审核中 |

---

## ⚠️ 错误处理

### 情况 1：没有找到任何工作流
```
❌ 未找到任何工作流记录

在 .claude/runs/ 目录下没有找到任何工作流记录。
你可以说 "开始工作流" 或 "执行 XMind" 来创建新的工作流。
```

### 情况 2：指定的 run-id 不存在
```
❌ 未找到工作流: run-20260509-999999

可用的工作流（说 "恢复 + 编号" 即可）：
  1. run-20260509-131320 - Button 组件开发 - 1/3 完成
  2. run-20260509-125105 - 工具函数开发 - 3/3 完成

示例：说 "恢复 1" 或 "恢复 run-20260509-131320"
```
