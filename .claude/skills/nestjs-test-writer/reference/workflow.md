# 工作流程

## 第一步：分析源文件

1. 识别测试目标类型（Controller / Service / Guard / Interceptor / Pipe / Middleware）
2. 识别所有公共方法和接口
3. 识别所有依赖（需要 mock 的依赖）
4. 识别方法参数、返回类型和可能的异常

## 第二步：制定测试计划

1. 确定每个方法需要覆盖的场景（成功 + 异常 + 边界条件）
2. 确定需要 mock 的依赖和返回值
3. 规划测试用例结构

## 第三步：生成完整测试代码

- 遵循模板结构
- 为每个公共方法生成至少两个测试用例
- 正确 mock 所有依赖
- 使用 AAA 模式组织代码
