# 安全检查清单

## 1. 认证与授权（最高风险）

检查清单：
- [ ] JWT 密钥是否从环境变量读取（**禁止硬编码**）
- [ ] JWT 密钥长度是否足够（至少 32 字符）
- [ ] 是否配置了合理的过期时间（accessToken 建议 2 小时以内）
- [ ] 需要认证的接口是否正确使用 JWT 认证守卫
- [ ] 是否检查当前用户只能访问自己的资源（防止水平越权）
- [ ] 权限检查是否在服务层验证（不只是控制器）
- [ ] 密码是否使用 Argon2id 正确加密存储（禁止使用 bcrypt）
- [ ] Token 是否优先从 HttpOnly Cookie 提取
- [ ] 是否支持单设备登出和全部设备登出功能
- [ ] Refresh Token 是否存储在 Redis 中并设置合理过期时间

---

## 2. 输入验证（高风险）

检查清单：
- [ ] 所有用户输入（query/param/body）都有 DTO 定义
- [ ] 每个字段都添加了 `class-validator` 验证装饰器
- [ ] 字符串验证是否限制最大长度（防止巨型输入攻击）
- [ ] 数字验证是否限制合理范围
- [ ] 枚举输入是否验证只允许预定值
- [ ] 是否使用白名单验证（只允许预期的值，不是黑名单）
- [ ] 邮箱、手机号、身份证等格式是否正确验证
- [ ] 是否对特殊字符进行适当过滤或转义

---

## 3. SQL 注入防护

检查清单：
- [ ] 是否全程使用 Prisma ORM，没有直接拼接原生 SQL
- [ ] 如果必须使用原生 SQL，是否正确使用参数化查询
- [ ] 用户输入没有直接拼接进 SQL 字符串
- [ ] 查询条件正确使用 Prisma 参数绑定
- [ ] 是否使用 Prisma 的 `$queryRawUnsafe` 等危险 API（需特别审查）
- [ ] 是否存在 OR 条件注入风险

---

## 4. XSS 跨站脚本防护

检查清单：
- [ ] 存储用户输入时是否保留原始数据（转义交给前端）
- [ ] 如果后端需要输出 HTML，是否正确转义用户输入
- [ ] 富文本输入是否过滤掉 `<script>` 等危险标签
- [ ] 用户提供的 HTML 没有直接返回给前端
- [ ] 模板渲染时是否使用安全的模板引擎配置

---

## 5. CSRF 防护

检查清单：
- [ ] 是否启用 CSRF 保护中间件（如 `csurf`）
- [ ] Cookie 是否配置 `SameSite: strict` 或 `lax`
- [ ] 敏感操作是否要求 CSRF Token
- [ ] 表单提交是否包含 CSRF Token 字段

---

## 6. 敏感信息泄露

检查清单：
- [ ] 代码中没有硬编码密钥、密码、API Key、数据库地址
- [ ] 环境变量文件 `.env` 已加入 `.gitignore`
- [ ] 错误响应不包含栈信息、内部路径、数据库结构给前端
- [ ] 日志不记录敏感信息（密码、token、身份证、手机号）
- [ ] 不把敏感信息打印到 `console.log`
- [ ] Swagger 文档没有暴露在内网环境外
- [ ] 接口响应中不返回敏感字段（密码哈希、内部 ID 等）
- [ ] 配置文件中没有生产环境的敏感配置

---

## 7. 配置安全

检查清单：
- [ ] 生产环境关闭 debug 模式和详细错误
- [ ] CORS origin 是否有白名单限制（不是 `*` 允许所有）
- [ ] 设置了合理的服务器超时时间
- [ ] 禁用了不必要的 HTTP 方法和端点
- [ ] 安全响应头已正确配置（CSP、X-Frame-Options、HSTS 等）
- [ ] Cookie 配置是否启用 HttpOnly、Secure、SameSite
- [ ] 是否禁用了 `X-Powered-By` 响应头
- [ ] 是否配置了 `X-Content-Type-Options: nosniff`

---

## 8. 错误与异常处理

检查清单：
- [ ] catch 块不吞掉异常（至少记录日志）
- [ ] 认证失败返回通用错误消息（不透露"用户名不存在"还是"密码错误"）
- [ ] 不对前端暴露内部系统信息
- [ ] 401/403 状态码使用正确（未认证 vs 未授权）
- [ ] 是否使用统一的异常过滤器处理所有异常
- [ ] 生产环境是否隐藏详细错误堆栈信息

---

## 9. 文件上传/下载（如有）

检查清单：
- [ ] 文件类型验证只允许预期的扩展名/MIME 类型
- [ ] 文件名是否处理防止路径遍历攻击（如 `../`）
- [ ] 上传文件存储在非 web 可访问目录
- [ ] 文件大小限制防止巨型文件攻击
- [ ] 下载时正确设置 Content-Type 防止浏览器执行恶意文件
- [ ] 是否验证文件内容而非仅依赖扩展名
- [ ] 文件名是否重新命名防止恶意文件名

---

## 10. 日志安全

检查清单：
- [ ] 日志不记录用户敏感信息（密码、Token、身份证、手机号）
- [ ] 日志写入前验证不包含恶意字符（防止日志注入）
- [ ] 错误日志不包含敏感请求头（Authorization、Cookie）
- [ ] 日志级别是否根据环境配置（生产环境禁用 debug 级别）
- [ ] 是否避免在日志中记录完整的请求体

---

## 11. 业务逻辑安全

检查清单：
- [ ] 删除/修改操作一定校验资源所有权（只能操作自己的数据）
- [ ] 批量操作是否限制数量防止暴力请求
- [ ] 分页查询限制最大 `pageSize` 防止全表拉取
- [ ] 敏感操作（如登录）是否有限流/防暴力破解
- [ ] 竞态条件是否使用事务保护
- [ ] 敏感操作是否要求二次确认或验证码
- [ ] 重复提交是否有幂等性保护

---

## 12. 限流与防暴力破解

检查清单：
- [ ] 登录接口是否有限流保护
- [ ] 注册接口是否有限流保护
- [ ] 密码找回接口是否有限流保护
- [ ] 敏感操作是否有请求频率限制
- [ ] 是否使用 Redis 实现分布式限流

---

## 13. 依赖安全

检查清单：
- [ ] 是否定期执行依赖安全审计（`npm audit`）
- [ ] 是否存在已知漏洞的依赖包
- [ ] lock 文件是否已提交（确保依赖版本一致性）
- [ ] 是否使用了废弃或不再维护的依赖

---

## 14. Redis 安全（如有使用）

检查清单：
- [ ] Redis 是否设置了密码认证
- [ ] Redis 端口是否仅绑定内网地址
- [ ] 是否禁用了危险命令（如 `FLUSHALL`、`CONFIG`）
- [ ] Token 存储是否设置了合理的过期时间
- [ ] Redis 连接是否使用 TLS（生产环境）

---

## 15. 并发安全

检查清单：
- [ ] 库存扣减、余额更新等操作是否使用事务
- [ ] 是否存在竞态条件导致数据不一致
- [ ] 是否使用乐观锁或悲观锁保护关键操作
- [ ] 数据库事务隔离级别是否配置合理
