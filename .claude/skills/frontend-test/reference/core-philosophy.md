# 核心哲学

## 用户行为测试，而非实现细节测试

- 测试用户可见的行为和结果，例如渲染内容、点击回调、状态变化对 UI 的影响
- 不要直接访问内部 state 或私有方法

## 测试金字塔

- **单元测试**：覆盖工具函数、自定义 Hooks、简单组件
- **集成测试**：覆盖组件交互和数据流
- **E2E 测试**：覆盖关键用户流程（如需要）

## 单一职责

一个测试用例只测试一件事情，保持测试简洁聚焦。

## 可重复运行

测试不应依赖外部状态，每次运行结果应一致。

## AAA 模式

遵循 Arrange-Act-Assert 模式组织测试代码，提高可读性：

- **Arrange**：准备测试数据和依赖
- **Act**：执行被测动作
- **Assert**：断言期望结果
