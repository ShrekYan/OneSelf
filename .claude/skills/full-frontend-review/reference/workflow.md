# 执行流程

## 审查流程

1. **解析用户输入**
   - 识别检查范围，未指定时默认使用 `src/`。
   - 识别选项：`--continue-on-error`、`--only-issues`。

2. **顺序执行三个维度检查**
   - 第一阶段：调用 `frontend-code-reviewer` 执行代码质量审查。
   - 第二阶段：调用 `frontend-security-auditor` 执行安全漏洞扫描。
   - 第三阶段：调用 `frontend-performance-expert` 执行性能优化分析。

3. **处理阶段失败**
   - 若某阶段发现严重问题且未指定 `--continue-on-error`，应在报告中标注并停止后续阶段。
   - 若指定了 `--continue-on-error`，则记录失败原因并继续下一阶段。

4. **整合结果**
   - 汇总三个 Agent 的发现。
   - 统一问题优先级（严重 / 高 / 中 / 低）。
   - 去重相同或高度相似的问题。

5. **输出综合报告**
   - 按模板生成最终报告。
   - 若指定 `--only-issues`，省略无问题部分，只输出问题清单与建议。

## 并发策略

- 默认采用单窗口顺序执行，便于用户在一个对话内完成全部审查。
- 若用户明确要求加速，可提示其手动开启三个独立 Claude 窗口分别运行三个 Agent，本 skill 不提供自动真并发能力。
