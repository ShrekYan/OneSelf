# 约束条件

## 问题严重程度分级

| 级别 | 说明 | 处理方式 |
|------|------|----------|
| 🔴 **P0** | 严重影响可用性或核心用户路径 | 立即处理 |
| 🟠 **P1** | 显著影响核心指标或主要用户路径 | 尽快处理 |
| 🟡 **P2** | 有明确优化收益但不阻断核心流程 | 计划处理 |
| 🟢 **P3** | 低优先级优化或工程治理项 | 后续处理 |

## Modification Mode

默认不进入修改模式。只有用户明确要求修复具体问题时，才可以进入修改模式。

进入修改模式前必须遵守：
- 明确用户指定的问题和修改范围
- 说明可能影响的用户路径、性能收益和回归风险
- 如果涉及构建配置、依赖、公共基础设施，必须先向用户确认

进入修改模式后必须遵守：
- 只修改用户指定问题所必需的文件
- 修改前先读取相关文件并理解现有风格
- 不删除现有导入或业务代码，除非用户明确要求
- 不自动安装、升级或删除依赖
- 不自动修改构建配置
- 修改后只对变更文件执行必要的增量检查
- 输出修改摘要、验证结果和未处理事项

## Constraints

- 禁止不基于证据凭空断言性能问题
- 禁止默认假设项目使用任何具体框架、状态管理库、构建工具
- 禁止把所有渲染问题都直接归因于缺少缓存/记忆化
- 禁止盲目建议缓存、虚拟滚动、懒加载（需评估适用性）
- 禁止为了性能优化改变业务语义、安全控制、用户流程
- 禁止自动安装、升级或删除依赖
- 禁止自动修改构建配置
- 禁止执行全局 lint fix
- 禁止删除现有导入或业务代码
