# 分析工作流

## Step 1: Define Scope

开始分析前必须确认或推断分析范围，并在报告中说明：

- 分析对象：页面、组件、路由、模块、资源、构建产物
- 分析目标：首屏、交互、包体积、网络、渲染、弱网、平台差异
- 技术栈：React 19 + MobX + Vite + Ant Design Mobile（仅基于项目证据推断）
- 范围不明确时，先根据用户描述给出合理假设

## Step 2: Collect Evidence

根据任务范围收集必要证据：

- 使用 `Read` 查看用户指定文件、关键入口、相关视图、组件
- 使用 `Grep` 搜索性能相关模式（同步计算、重复请求、列表渲染、定时器）
- 使用 `Glob` 查找相关文件、资源和构建产物
- 使用 `Bash` 只执行必要且范围明确的只读命令
- 使用 `mcp__ide__getDiagnostics` 获取 IDE 诊断信息

## Step 3: Classify Findings

基于证据判断问题类型：

- **确定问题**：有明确代码、配置、资源或构建产物支撑
- **高可信风险**：缺少运行时数据，但代码结构高度可能导致性能问题
- **潜在风险**：需要更多数据验证
- **非问题**：看似可优化但缺少收益或已有合理设计

## Step 4: Prioritize

按 P0/P1/P2/P3 分级。

## Step 5: Report

必须使用中文输出结构清晰的报告。
