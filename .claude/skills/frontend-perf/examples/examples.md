# 示例交互

## 场景 1：首屏加载慢分析

**用户请求**: "首页加载很慢，Lighthouse 分数只有 50 分，帮我分析一下"

**Agent 响应**:
```
我来分析首页加载性能问题。首先需要系统性扫描页面代码。
```

**执行步骤**:
1. 读取 `apps/web/src/pages/index/index.tsx`
2. 读取 `apps/web/src/api/request-cache.ts` 了解缓存配置
3. 检查路由配置和懒加载设置
4. 分析 bundle 体积

**发现问题**:
- 🔴 P0 - 列表页组件 `ProductList` 未使用虚拟滚动，一次性渲染 200+ 项
- 🔴 P0 - 5 个 API 请求未启用缓存，重复进入页面重复请求
- 🟠 P1 - 图片未设置宽高比，导致 CLS 0.25
- 🟠 P1 - 路由未配置懒加载，所有页面代码打包在一起

**输出**: 提供完整的性能分析报告和优化方案

## 场景 2：滚动卡顿优化

**用户请求**: "商品列表页滚动很卡，尤其是快速滑动的时候"

**Agent 响应**:
```
我来分析滚动卡顿问题。主要关注渲染性能和长任务。
```

**执行步骤**:
1. 使用 React DevTools Profiler 录制滚动操作
2. 检查列表项组件是否被 `observer` 正确包裹
3. 检查是否有不必要的重渲染
4. 检查滚动事件是否防抖

**发现问题**:
- 🔴 P0 - 列表项内部引用了父级未 memo 的 props，导致每次父组件渲染列表项都重渲染
- 🔴 P0 - 滚动事件 `onScroll` 未防抖，每次滚动触发 60+ 次更新
- 🟠 P1 - 列表项内部有重复的 computed 计算

**输出**: 提供代码修改方案和验证方法

## 场景 3：内存泄漏排查

**用户请求**: "页面使用一段时间后变得越来越卡，退出去再进来又好了"

**Agent 响应**:
```
这是典型的内存泄漏症状。我来排查泄漏点。
```

**执行步骤**:
1. 检查 `useEffect` cleanup 函数是否正确实现
2. 检查 `setInterval`/`setTimeout` 是否在 cleanup 中清除
3. 检查 MobX reaction 是否在组件卸载时清理
4. 检查全局 Map/Set 是否有无限增长

**发现问题**:
- 🔴 P0 - `useEffect` 中的 `setInterval` 未在 cleanup 中 `clearInterval`
- 🔴 P0 - 图片懒加载组件的缓存 Map 无限增长
- 🟠 P1 - 路由缓存未限制大小

**输出**: 提供修复代码和内存泄漏验证方法
