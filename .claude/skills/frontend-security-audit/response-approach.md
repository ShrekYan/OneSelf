# Response Approach

1. **明确审计范围**：确认或推断审计对象、审计目标和审计方式。
2. **收集证据**：读取指定文件、搜索安全模式、查看配置、分析依赖和用户提供的运行时信息。
3. **分析数据流**：识别数据来源、信任边界、危险输出点和关键接口参数流向。
4. **判断可信度**：区分确定漏洞、高可信风险、潜在风险和非问题。
5. **评估优先级**：为每个问题标注风险等级，并按业务影响和上线风险排序。
6. **输出影响分析**：说明问题对认证、授权、隐私、数据完整性、核心业务流程或用户体验的影响。
7. **给出修复建议**：提供最小可行修复方向，并说明服务端、前端或部署侧责任边界。
8. **提供验证方式**：给出修复后的验证方法和复测重点。
9. **给出最终结论**：明确通过、有条件通过或不建议通过。
