# XMind 自动化执行最佳实践

## 任务粒度

每个任务应对应一个原子功能：

- 一个组件
- 一个接口
- 一个页面
- 一个独立的配置或工具函数

避免将多个独立目标合并到一个任务中，否则生成的方案会过于复杂，审核和执行难度都会增加。

## 依赖关系

- 同模块内的任务会按顺序自动推断依赖关系。
- 跨模块依赖需要显式标注：

```markdown
- 显式依赖：T001
```

- 避免创建循环依赖。
- 依赖标注应准确，错误的依赖会导致执行顺序混乱。

## 业务描述

任务描述越清晰，生成的方案越准确。建议包含：

- 明确的目标描述
- 必要的上下文信息
- 具体的验收标准
- 特殊约束条件

## 审核时沟通

如果生成的方案不符合预期，直接提出修改意见。常见修改包括：

- 调整实现顺序
- 补充遗漏的边界情况
- 修改技术选型
- 拆分或合并任务

## 质量门禁

每个任务执行后默认检查：

- lint
- TypeScript 类型检查

根据任务类型，可能还需要补充：

- 单元测试
- 构建验证
- 代码审查

## 风险控制

- 高风险任务应生成更详细的方案。
- 涉及数据库、认证、支付等敏感操作的任务需要额外谨慎。
- 不确定时优先选择"修改方案"而非直接执行。
