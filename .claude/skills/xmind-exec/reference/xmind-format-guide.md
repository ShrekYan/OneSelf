# XMind Markdown 编写规范

## 适用范围

本文档定义 XMind 导出为 Markdown 后，能够被 `xmind-exec` 正确解析的任务格式。遵循本规范可提升任务提取的准确率，减少解析失败或要素缺失。

## 基本结构

XMind Markdown 只需包含业务需求，技术规范由项目自动注入。推荐结构如下：

```markdown
# 项目名称

## 模块名

### 任务名

- 目标描述：任务要实现的核心目标
- 上下文：相关背景、前置状态、依赖信息
- 质量标准：验收条件、测试要求、性能要求
- 约束条件：特殊限制、禁止事项、技术约束
- 依赖：T001, T002（可选）
```

## 任务要素

解析脚本会尝试从每个任务节点中提取以下要素：

| 要素 | 关键词 | 说明 |
|------|--------|------|
| 目标 | 目标描述、目标、功能、功能描述、要实现 | 任务的核心目标，必填 |
| 上下文 | 上下文、上下文信息、背景、背景信息 | 任务背景和相关状态 |
| 质量标准 | 质量标准、验收标准、质量要求、要求 | 验收条件和质量要求 |
| 约束条件 | 约束条件、约束、限制、限制条件 | 特殊约束和禁止事项 |

## 支持的表达格式

以下四种格式均可被识别：

### 格式 1：同一行冒号分隔

```markdown
- 目标描述：实现用户登录页面
- 上下文：H5 移动端登录流程
```

### 格式 2：关键词带冒号，值在下一行缩进

```markdown
- 目标描述：
  - 实现用户登录页面
  - 支持手机号和密码输入
```

### 格式 3：关键词单独一行，值在下一行缩进带列表符号

```markdown
- 目标描述
  - 实现用户登录页面
  - 支持表单验证
```

### 格式 4：关键词单独一行，值在下一行缩进为纯文本

```markdown
- 目标描述
  实现用户登录页面，包含手机号输入、密码输入和登录按钮。
```

## 执行模式标注

解析脚本会根据任务内容自动推断执行模式：

| 模式 | 触发关键词 | 说明 |
|------|------------|------|
| plan-only | 只出方案、仅方案、不执行 | 只生成方案，不执行代码 |
| auto-exec | 自动执行、直接执行 | 生成方案后直接执行 |
| review-first | 其他情况（默认） | 生成方案后等待用户确认 |

## 显式依赖标注

如果任务依赖其他任务，可在内容中标注：

```markdown
- 显式依赖：T001
```

或

```markdown
- 依赖：T001, T002
```

同模块内的任务会按顺序自动推断依赖关系。

## 注意事项

- 每个任务节点应聚焦一个原子功能（一个组件、一个接口、一个页面）。
- 避免在单个任务节点中混合多个独立目标。
- 任务描述越清晰，生成的执行方案越准确。
