# XMind 自动化执行详细工作流

## 执行流程

```
1. 初始化运行环境
   └── 自动创建 .claude/runs/run-{timestamp}/ 目录

2. 解析 XMind 生成任务清单
   └── 生成 task-manifest.json
   └── 生成 execution-plan.md
   └── 复制源文件为 task-definition.md

3. 确认执行计划
   └── 用户确认整体任务清单

4. 逐条审核执行（核心）
   ┌── 对每个任务：
   │     a. 生成详细执行方案 scheme.md
   │     b. 展示方案供用户审核
   │     c. 用户选择：确认执行 / 修改方案 / 跳过 / 终止
   │     d. 执行任务（生成代码 + 质量检查）
   │     e. 保存执行结果
   └── 循环直到所有任务完成

5. 生成最终交付报告
   └── final-report.md
```

## 运行时文件结构

```
.claude/runs/run-{timestamp}/
├── run-info.json                # 运行基本信息
├── task-manifest.json          # 任务清单
├── execution-plan.md            # 完整执行计划
├── task-definition.md           # 原始 XMind Markdown 副本
├── tasks/                       # 每个任务独立目录
│   ├── T001/
│   │   ├── scheme.md            # 任务执行方案
│   │   ├── review-comments.md   # 审核意见（如有）
│   │   ├── execution-result.md  # 执行结果
│   │   ├── changed-files.json   # 修改文件清单
│   │   └── status.json          # 任务状态
│   ├── T002/
│   └── T003/
└── final-report.md              # 最终交付报告
```

## 审核模式特点

| 特点 | 说明 |
|------|------|
| 风险可控 | 每个任务都可以审核后再执行 |
| 方案透明 | 每个任务做什么、改哪些文件一目了然 |
| 可干预 | 随时可以修改方案或跳过任务 |
| 结果可追溯 | 所有中间文件都持久化保存 |

## 任务状态看板

解析完成后会进入任务状态看板，显示：

- 工作流版本
- 运行目录
- 解析版本
- 当前状态
- 锁保护状态
- 任务列表及状态

## 可用指令

在看板中可输入以下指令（严格匹配，大小写不敏感）：

| 指令 | 说明 |
|------|------|
| `T001` | 选择 T001，进入方案生成确认 |
| `exec T001` | 强制直接执行 T001（慎用） |
| `status` | 刷新显示状态看板 |
| `report` | 查看执行报告 |
| `exit` | 退出工作流 |

## 并发安全

当前工作流采用单进程持有锁的方式保证并发安全：

- 全程持有目录锁，物理多开安全。
- 锁 TTL 为 10 分钟，过期自动清理。
- 所有状态在内存中传递，不落地到全局文件。
