# XMind 任务解析层级方案汇总

> **版本**: v3.0 | **适用**: xmind-task-parser Agent | **更新日期**: 2026-05-10

---

## 🎯 黄金层级结构（3-4 层最佳）

| 层级                | 名称        | 作用                         | 粒度标准             |
| ------------------- | ----------- | ---------------------------- | -------------------- |
| **第 1 层**         | 项目根节点  | 项目名称 + 业务领域          | 一句话说清什么项目   |
| **第 2 层**         | 大模块/阶段 | 按业务模块或开发阶段划分     | 3-5 个模块最佳       |
| **第 3 层**         | 可执行任务  | 具体开发任务（最小执行单元） | 1 个人 1-2 天能做完  |
| **第 4 层（可选）** | 任务详情    | 验收标准、约束、依赖说明     | 补充信息，非必须执行 |

---

## 📋 每层详细规范

### 第 1 层：项目根节点

```
✅ 正确示例: 📦 小贝3项目 - 发车业务模块
❌ 错误示例: 小贝（太简单，不知道做什么）
```

- 包含：项目名 + 业务领域
- 建议加 emoji 前缀区分类型

### 第 2 层：大模块/阶段

```
✅ 正确示例: 📂 开发前准备、📂 绘制组件、📂 联调测试
❌ 错误示例: 后端（太笼统）
```

- 按**开发阶段**或**业务模块**划分
- 数量控制在 3-6 个
- 建议统一 emoji 前缀

### 第 3 层：可执行任务（核心层）

```
✅ 正确示例: ✅ T001 新增普通发车模块接口 /v1/normal/departDetail
❌ 错误示例: 做接口（太模糊）
```

- **必须加编号**: T001, T002... （后续依赖关系要用）
- 一句话说清"做什么 + 关键信息"
- 粒度：1-2 天能完成的工作量

### 第 4 层：任务详情（可选）

```
✅ 正确示例:
   🔹 路径: /v1/normal/departDetail
   🔹 约束: 只新增不修改其他
   🔹 依赖: T001
   🔹 预计工时: 4小时
```

- 补充任务的验收标准、约束条件
- **依赖关系在这里定义**（见下一章）

---

## 🔗 依赖关系定义方式（3 选 1）

### 方式一：节点备注写（推荐 ⭐⭐⭐）

在 XMind 节点的**备注**里加一行：

```
依赖: T001
依赖: T001, T002 （多个用逗号分隔）
```

### 方式二：标题后缀写

在节点标题末尾加括号：

```
T005 - 使用mock数据填充页面信息 (依赖: T004)
```

### 方式三：XMind 关系连线

用 XMind 的「关系」工具画箭头线，**箭头指向谁就依赖谁**

## 📝 完美结构示例

```
📦 小贝3项目 - 发车业务模块（第1层）
├── 📂 开发前准备（第2层）
│   ├── ✅ T001 新增普通发车模块接口（第3层）
│   │   ├── 🔹 路径: /v1/normal/departDetail（第4层）
│   │   ├── 🔹 约束: 只新增不修改其他
│   │   └── 🔹 依赖: 无
│   │
│   └── ✅ T002 定义普通发车枚举
│       ├── 🔹 fofDetailTypeCode: 0003
│       ├── 🔹 subscriptionTypeCodes: 80
│       └── 🔹 依赖: T001
│
└── 📂 绘制组件（第2层）
    ├── ✅ T003 创建发车组件静态资源模版
    ├── ✅ T004 根据截图生成HTML结构
    │   └── 🔹 依赖: T003
    └── ✅ T005 使用mock数据填充页面信息
        └── 🔹 依赖: T004
```

## ❌ 禁忌清单（避坑指南）

| 错误做法                                  | 后果                           |
| ----------------------------------------- | ------------------------------ |
| 只有 2 层结构（项目 → 大任务）            | 任务太笼统，没法拆成可执行单元 |
| 超过 5 层结构                             | 层级太深，看不清整体节奏       |
| 任务粒度太大（"做整个发车模块"）          | 一个任务要做一周，没法跟踪进度 |
| 任务粒度太小（"写 controller 的 import"） | 太碎，增加管理成本             |
| 不给任务加编号                            | 无法定义依赖关系               |
| 任务标题太模糊（"做接口"）                | 不知道具体做什么，容易理解偏差 |

## ✅ 快速检查清单

创建完 XMind 后过一遍：

- [ ] 一共 3-4 层结构？
- [ ] 每个可执行任务都有编号（T001...）？
- [ ] 每个任务 1-2 天能做完？
- [ ] 依赖关系定义清楚了？
- [ ] 没有超过 5 层的深度？
- [ ] 任务标题清晰，看完就知道做什么？
