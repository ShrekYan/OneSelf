# XMind → AI 工作流 - 快速开始指南

> 5 分钟上手，让 AI 帮你执行重复劳动

---

## 🚀 三步开始使用

### 第一步：在 XMind 中拆分任务

按照 `docs/XMind-使用示例模板.md` 规范，在 XMind 中拆分任务：

```
# 我的项目 - 功能开发

## 公共组件
### 实现弹窗组件
### 实现进度条组件

## API 层
### 定义详情接口类型
### 定义提交接口类型

## 页面层
### 实现页面布局
### 实现业务逻辑
```

### 第二步：导出 Markdown

在 XMind 中：

1. 文件 → 导出 → Markdown
2. 保存到项目 `docs/` 目录下，如：`docs/my-feature-xmind.md`

### 第三步：在 Claude 中执行

```bash
/xmind-exec docs/my-feature-xmind.md
```

然后：

1. AI 解析生成任务清单
2. 展示执行计划
3. 确认后自动执行所有任务
4. 最后生成交付报告

## 📋 完整使用示例

### 1. 编写 XMind

```markdown
# 策略详情页 - 普通发车功能

## 公共组件

### 实现普通发车弹窗组件

- 业务目标：实现可复用的普通发车弹窗
- 输出规范：支持标题、内容、按钮自定义

### 实现进度条组件

- 业务目标：实现动态进度条展示
- 输出规范：支持 0-100% 进度展示

## API 层

### 定义发车详情接口

### 定义跟投接口

## 页面层

### 实现策略详情页布局

### 实现普通发车业务逻辑
```

### 2. 执行命令

```bash
/xmind-exec docs/strategy-detail-xmind.md
```

### 3. 确认执行计划

AI 会输出类似内容：

```
📋 执行计划确认
========================================
总任务数：6 个
预计执行时间：30 分钟

执行顺序：
  T001 - 实现普通发车弹窗组件（公共组件，Agent: frontend-developer）
  T002 - 实现进度条组件（公共组件，Agent: frontend-developer）
  T003 - 定义发车详情接口（API 层，Agent: frontend-developer）
  T004 - 定义跟投接口（API 层，Agent: frontend-developer）
  T005 - 实现策略详情页布局（页面层，Agent: frontend-developer）
  T006 - 实现普通发车业务逻辑（页面层，Agent: frontend-developer）

  ✅ Lint 检查

是否开始执行？[Y/n]
```

输入 `Y` 开始执行。

## 💡 最佳实践

### ✅ 推荐做法

1. **任务粒度适中**
   - 每个任务 5-15 分钟 AI 执行时间
   - 一个任务只做一件事

2. **模块划分清晰**
   - 公共组件、API 层、页面层分开
   - 无依赖的模块可以并行

3. **描述具体明确**
   - 好："实现包含标题、确认/取消按钮的弹窗组件"
   - 不好："做个弹窗"

### ❌ 避免做法

1. 不要一个任务包含多个不相关功能
2. 不要描述太模糊
3. 不要任务粒度太大

## 🆘 常见问题

### Q: 任务执行失败了怎么办？

A: 交付报告中会列出需人工关注项，包含错误详情和修复建议。可以手动修复后继续。

### Q: 可以中途停止执行吗？

A: 可以，随时中断，已执行的任务会保留。

### Q: 可以只执行部分任务吗？

A: 目前是按计划全部执行。如果只需要部分任务，可以在 XMind 中只保留需要的任务。

### Q: 质量检查不通过会怎样？

A: 会先尝试自动修复（如 lint --fix），如果修复失败，会记录到需人工关注项。
