# XMind 工作流 - 纯人工控制模式使用说明

## 🎯 核心理念

**AI 完全被动，人拥有 100% 控制权**

- ❌ AI 不主动推进任何任务
- ❌ 没有"自动逐条执行"
- ✅ 所有执行时机、执行顺序完全由人决定
- ✅ AI 只响应人的具体指令

---

## 📋 完整流程

```
1. 用户准备 XMind Markdown 文件
   ↓
2. 运行 /workflow xmind-exec file_path
   ↓
3. 初始化运行目录
   ↓
4. 调用 xmind-task-parser 解析
   ↓
5. 生成 task-manifest.json + task-status.json + execution-plan.md
   ↓
6. 显示状态看板，等待人工指令
   ↓
[用户输入指令，循环响应]
```

---

## 🎮 可用指令列表

| 指令        | 说明                                           |
| ----------- | ---------------------------------------------- |
| `T001`      | 生成 T001 完整代码方案 → 人工审核 → 确认后执行 |
| `view T001` | 只生成并查看 T001 方案，不执行（用于预览）     |
| `status`    | 刷新显示状态看板                               |
| `report`    | 查看当前执行报告（已完成任务、修改文件清单等） |
| `exit`      | 退出工作流，生成最终交付报告                   |

---

## ✨ 智能化特性：全部完成自动生成报告

### 触发条件

每次执行完一个任务后，系统自动检查 `task-status.json`：

- 如果**还有 pending 状态的任务** → 正常显示状态看板，等待下一个指令
- 如果**所有任务都是 completed 或 skipped** → **自动生成 final-report.md**

### 用户体验

```
✅ T003 执行完成！

========================================
📊 项目执行状态看板
========================================

  [✅] T001 - 实现字符串工具类型    (已完成 ✓)
  [✅] T003 - 实现数字工具函数      (已完成 ✓)
  [✅] T002 - 实现字符串工具函数    (已完成 ✓)

🎉 所有任务已完成，最终报告已生成
========================================
```

### 设计理念

> **高风险操作：人工审核确认**
> **低风险操作：自动执行**

| 操作类型                 | 风险   | 决策方           |
| ------------------------ | ------ | ---------------- |
| 执行业务任务（修改代码） | 高风险 | 人 100% 审核确认 |
| 生成最终报告（信息汇总） | 零风险 | AI 自动执行      |

这是"人在回路中"与"自动化"之间的最佳平衡点。

## 📁 运行时目录结构（完整可追溯）

```
.claude/runs/run-{id}/
├── run-info.json              # ✅ 运行基本信息（强制保存）
│                                - run_id, source_file, start_time, mode
│
├── task-manifest.json         # ✅ 任务清单（结构化）（强制保存）
│                                - 所有任务的完整信息：ID、业务目标、输入输出、依赖、agent_type...
│                                - 拓扑排序、并行分组、execution_plan
│
├── task-status.json           # ✅ 任务状态跟踪（强制保存）
│                                - 每个任务的状态: pending / reviewing / completed / skipped
│                                - 完成时间戳
│
├── execution-plan.md          # ✅ 人类可读执行计划（强制保存）
│                                - 项目概述、依赖关系图、甘特图、风险评估、质量门禁
│
├── final-report.md            # ✅ 最终交付报告（exit 时生成）
│                                - 执行概览、修改文件清单、验证步骤、Git Commit 建议
│
└── tasks/
    ├── T001/
    │   ├── scheme.md          # ✅ 任务完整方案（强制保存）
    │   │                        - 完整代码方案，供人工审核的原始记录
    │   │                        - 包含每个文件的完整代码（不是摘要）
    │   │
    │   └── result.md          # ✅ 执行结果 + 质量检查（强制保存）
    │                            - 质量检查记录（TypeScript / ESLint 结果）
    │                            - 实际创建/修改的文件列表
    │
    ├── T002/
    └── ...
```

## 📋 完整文件追溯清单（100% 可审计）

| 文件                    | 保存时机                | 负责人                   | 可追溯内容                          |
| ----------------------- | ----------------------- | ------------------------ | ----------------------------------- |
| `run-info.json`         | 初始化时                | workflow                 | 谁、什么时候、从哪个 XMind 文件启动 |
| `task-manifest.json`    | 解析完成后              | xmind-task-parser        | 完整任务清单、依赖关系、并行分组    |
| `task-status.json`      | 初始化 + 每次任务完成后 | workflow + task-executor | 每个任务的状态变迁、完成时间        |
| `execution-plan.md`     | 解析完成后              | xmind-task-parser        | 甘特图、依赖关系图、风险评估        |
| `tasks/T{id}/scheme.md` | 生成方案后              | task-executor            | 人工审核的完整代码方案记录          |
| `tasks/T{id}/result.md` | 任务完成后              | task-executor            | 质量检查结果、实际创建的文件        |
| `final-report.md`       | 输入 exit 时            | task-executor            | 最终交付汇总、验证建议              |

---

## ✅ 零容忍规则（确保可追溯）

1. ❌ 禁止只在对话中展示方案而不保存 `scheme.md`
2. ❌ 禁止只执行任务而不保存 `result.md`
3. ❌ 禁止执行后不更新 `task-status.json`
4. ❌ 禁止方案使用摘要而不写出完整代码
5. ❌ 禁止跳过任何质量检查就标记任务完成

所有规则已编码到 `task-executor.md` Agent 配置中强制执行。

## 💡 最佳实践

### 1. 灵活调整执行顺序

不需要按编号顺序执行！可以：

- 先做简单的任务建立信心
- 先做关键路径的任务
- 同并行组的任务可以穿插执行

### 2. 先 view 再执行

不确定方案质量时：

1. 先 `view T001` 预览方案
2. 提出修改意见
3. 满意后再输入 `T001` 执行

### 3. 随时查看状态

输入 `status` 随时了解当前进度，避免重复执行

## ✅ 模式优势对比

| 特性         | 自动模式         | 纯人工控制模式     |
| ------------ | ---------------- | ------------------ |
| 控制权       | 机器主导         | 人 100% 主导       |
| 灵活性       | 低（必须按顺序） | 高（任意顺序）     |
| 控制感       | 弱               | 强                 |
| 真实开发体验 | 差               | 好                 |
| 并行能力发挥 | 弱（只是概念）   | 强（真正自由选择） |
| 适合场景     | 简单、无风险任务 | 真实项目开发       |
