# Claude Code 官方支持的文件引用与加载方式

> 本文档整理 Claude Code 官网明确支持的文件引用、规则加载、Skill 辅助文件、动态上下文注入、Subagent 预加载 Skill 等机制，作为学习和配置参考。

---

## 1. `CLAUDE.md` / `CLAUDE.local.md` 中使用 `@path` 导入文件

### 适用场景

用于把其他说明文件导入到 `CLAUDE.md` 或 `CLAUDE.local.md` 中。导入文件会在会话启动时展开，并加载进 Claude Code 上下文。

常见用途：

- 导入项目 README
- 导入 `package.json`
- 导入团队工作流文档
- 导入个人偏好配置
- 复用已有的 `AGENTS.md`

### 基础案例

```md
# CLAUDE.md

# 项目说明

See @README.md for project overview.

# 项目命令

@package.json

# Git 工作流

@docs/git-instructions.md
```

### 个人本地配置案例

```md
# CLAUDE.local.md

# 我的个人项目偏好

@~/.claude/my-project-instructions.md
```

### 递归导入案例

```md
# CLAUDE.md

@.claude/project-index.md
```

```md
# .claude/project-index.md

@rules/000-forbidden.md
@rules/100-tech-stack.md
```

### 官方规则

- 支持相对路径和绝对路径。
- 相对路径相对于包含 `@path` 的文件解析，不是相对于当前工作目录。
- 导入文件会展开并加载进上下文。
- 支持递归导入。
- 最大递归深度为 4 层。
- 第一次遇到外部导入时，Claude Code 会弹出审批。
- 如果拒绝审批，导入会保持禁用，并且不会再次弹窗。

## 2. `.claude/rules/` 规则文件自动加载

### 适用场景

用于把较大的项目规范拆分成多个规则文件，避免 `CLAUDE.md` 过长。

常见用途：

- 代码风格规范
- 测试规范
- 安全规范
- 前端规范
- 后端规范
- API 规范

### 目录案例

```text
your-project/
├── CLAUDE.md
└── .claude/
    └── rules/
        ├── code-style.md
        ├── testing.md
        └── security.md
```

### 规则文件案例

```md
# Code Style Rules

- Use 4 spaces for indentation.
- Prefer functional components.
- Do not introduce unnecessary dependencies.
```

### 官方规则

- `.claude/rules/` 下的 `.md` 文件会被 Claude Code 发现并加载。
- 支持递归子目录。
- 没有 `paths` frontmatter 的规则会无条件加载。
- 适合放通用、长期有效的项目规则。

## 3. `.claude/rules/` 路径匹配规则

### 适用场景

用于让某些规则只在 Claude Code 处理特定路径或特定类型文件时生效。

常见用途：

- 只对 API 文件生效的规则
- 只对 React 组件生效的规则
- 只对测试文件生效的规则
- 只对 Markdown 文档生效的规则

### 单路径案例

```md
---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules

- All API endpoints must include input validation.
- Use the standard error response format.
- Include OpenAPI documentation comments.
```

含义：当 Claude Code 处理匹配 `src/api/**/*.ts` 的文件时，这个规则会生效。

### 多路径案例

```md
---
paths:
  - "src/**/*.{js,jsx}"
  - "tests/**/*.test.js"
---

# JavaScript Rules

- Use existing project utilities.
- Keep test cases focused.
```

### 官方规则

- 使用 YAML frontmatter 中的 `paths` 字段声明匹配路径。
- 支持 glob pattern。
- 路径匹配规则在 Claude 读取匹配文件时触发。
- 适合降低上下文噪音，只在相关文件场景加载规则。

## 4. Skill 中引用 supporting files

### 适用场景

用于把一个 Skill 拆成主说明文件和辅助文件。`SKILL.md` 保持简洁，详细模板、示例、参考文档放到同目录其他文件中。

常见用途：

- 模板文件
- 示例文件
- 详细 API 文档
- 长篇规范文档
- 辅助脚本

### 目录案例

```text
.claude/skills/create-page/
├── SKILL.md
├── template.md
├── examples.md
└── scripts/
    └── validate.sh
```

### `SKILL.md` 案例

```md
---
name: create-page
description: Create a new page following project conventions
---

# Create Page

Follow the project page creation process.

## Additional resources

- For page template, see template.md
- For examples, see examples.md
```

### 官方规则

- Skill 可以包含多个辅助文件。
- `SKILL.md` 是入口文件，其他文件是 supporting files。
- 可以在 `SKILL.md` 中通过 Markdown 链接引用辅助文件。
- Markdown 链接不会自动展开文件内容。
- Claude 会知道这些文件存在，并在需要时读取。
- 官方建议 `SKILL.md` 保持简洁，把长篇资料放到 supporting files 中。

## 5. Skill 中使用 `` !`command` `` 动态注入命令输出

### 适用场景

用于在 Skill 内容发送给 Claude 前执行命令，并把命令输出插入到 Skill 内容中。

常见用途：

- 注入当前 `git diff`
- 注入 PR 信息
- 注入当前分支状态
- 注入某个文件的实时内容
- 注入环境信息

### 注入 `git diff` 案例

```md
---
name: summarize-changes
description: Summarize uncommitted changes
---

## Current changes

!`git diff HEAD`

## Instructions

Summarize the changes above.
```

运行 Skill 时，Claude Code 会先执行：

```bash
git diff HEAD
```

然后把命令输出替换到 `!` 语句所在位置。

### 注入 PR 信息案例

```md
---
name: pr-summary
description: Summarize changes in a pull request
---

## Pull request context

- PR diff: !`gh pr diff`
- PR comments: !`gh pr view --comments`
- Changed files: !`gh pr diff --name-only`

## Your task

Summarize this pull request.
```

### 官方规则

- `` !`command` `` 是动态上下文注入。
- 命令在 Claude 看到 Skill 内容之前执行。
- Claude 看到的是命令输出，不是命令本身。
- 命令输出作为普通文本插入，不会再次扫描其中的动态注入语法。
- 可以通过设置禁用 Skill shell execution。

## 6. Skill 中使用 fenced code block 动态注入多行命令

### 适用场景

用于执行多行命令并注入输出，比多个单行 `` !`command` `` 更清晰。

### 案例

````md
---
name: environment-check
description: Check local environment
---

## Environment

```!
node --version
npm --version
git status --short
```

## Instructions

Summarize the environment information.
````

### 官方规则

- 多行命令使用以 ```! 开头的 fenced code block。
- 命令输出会替换整个 fenced code block。
- 适合需要连续执行多条命令的场景。

## 7. Skill 中使用 `${CLAUDE_SKILL_DIR}` 引用当前 Skill 目录

### 适用场景

用于在动态命令中稳定引用当前 `SKILL.md` 所在目录，避免受到当前工作目录影响。

常见用途：

- 读取同目录模板文件
- 读取同目录参考文档
- 执行同目录脚本

### 目录案例

```text
.claude/skills/use-template/
├── SKILL.md
└── template.md
```

### `SKILL.md` 案例

```md
---
name: use-template
description: Use a local template file
---

## Template

!`cat "${CLAUDE_SKILL_DIR}/template.md"`

## Instructions

Generate code based on the template above.
```

### 官方规则

- `${CLAUDE_SKILL_DIR}` 表示当前 Skill 的目录。
- 对项目 Skill、个人 Skill、插件 Skill 都适用。
- 适合在 Skill 中引用自带脚本或模板文件。

## 8. Subagent 中使用 `skills:` 预加载 Skill

### 适用场景

用于让某个 Subagent 启动时自动获得指定 Skill 的完整内容。

常见用途：

- 前端开发 Agent 预加载页面创建规范
- 审查 Agent 预加载审查规范
- API Agent 预加载接口规范
- 测试 Agent 预加载测试规范

### Agent 案例

```md
---
name: frontend-developer
description: Frontend development agent
tools: Read, Write, Edit, Glob, Grep, Bash
model: inherit
skills:
  - create-page
  - lint-check
---

You are a frontend development agent.

Follow the preloaded skills.
```

### 对应目录案例

```text
.claude/
├── agents/
│   └── frontend-developer.md
└── skills/
    ├── create-page/
    │   └── SKILL.md
    └── lint-check/
        └── SKILL.md
```

### 官方规则

- `skills:` 是 Subagent frontmatter 支持字段。
- 预加载的是 Skill 的完整内容，不只是 description。
- Subagent 启动时，指定 Skill 内容会注入到上下文。
- 未列在 `skills:` 中的 Skill，Subagent 仍然可以通过 Skill 工具调用，前提是工具权限允许。
- 设置了 `disable-model-invocation: true` 的 Skill 不能被预加载。

## 9. Skill 参数替换：`$ARGUMENTS`

### 适用场景

用于接收用户调用 Skill 时传入的全部参数。

### 案例

```md
---
name: fix-issue
description: Fix a GitHub issue
---

Fix GitHub issue $ARGUMENTS following our coding standards.
```

调用：

```text
/fix-issue 123
```

实际效果：

```md
Fix GitHub issue 123 following our coding standards.
```

### 官方规则

- `$ARGUMENTS` 表示用户调用 Skill 时传入的完整参数字符串。
- 如果 Skill 内容中没有 `$ARGUMENTS`，Claude Code 会把参数追加到 Skill 内容末尾。

---

## 10. Skill 参数替换：`$ARGUMENTS[N]` / `$0`

### 适用场景

用于按位置读取用户传入的参数。

### `$ARGUMENTS[N]` 案例

```md
---
name: migrate-component
description: Migrate a component
---

Migrate the $ARGUMENTS[0] component from $ARGUMENTS[1] to $ARGUMENTS[2].
```

调用：

```text
/migrate-component SearchBar React Vue
```

实际效果：

```md
Migrate the SearchBar component from React to Vue.
```

### `$0` 简写案例

```md
---
name: migrate-component
description: Migrate a component
---

Migrate the $0 component from $1 to $2.
```

调用：

```text
/migrate-component SearchBar React Vue
```

实际效果相同：

```md
Migrate the SearchBar component from React to Vue.
```

### 官方规则

- `$ARGUMENTS[0]` 表示第一个参数。
- `$0` 是 `$ARGUMENTS[0]` 的简写。
- `$1` 是 `$ARGUMENTS[1]` 的简写。
- 多词参数需要用引号包裹。

---

## 11. Skill 命名参数：`$name`

### 适用场景

用于给位置参数命名，让 Skill 内容更可读。

### 案例

```md
---
name: create-component
description: Create a component
arguments:
  - componentName
  - category
---

Create the $componentName component under the $category category.
```

调用：

```text
/create-component UserCard Account
```

实际效果：

```md
Create the UserCard component under the Account category.
```

### 官方规则

- 在 frontmatter 中使用 `arguments` 声明参数名。
- 参数名按位置映射。
- `$componentName` 对应第一个参数。
- `$category` 对应第二个参数。

## 12. `.claude/commands/*.md` 兼容 Skill 行为

### 适用场景

旧版 custom commands 仍然可用。官网说明 custom commands 已合并到 Skills，但 `.claude/commands/` 文件继续兼容。

### 目录案例

```text
.claude/commands/review-changes.md
```

### 命令文件案例

```md
---
description: Review current changes
---

## Current diff

!`git diff HEAD`

## Instructions

Review the diff above.
```

调用：

```text
/review-changes
```

### 官方规则

- `.claude/commands/*.md` 仍然可以创建 slash command。
- 支持与 Skill 相同的 frontmatter。
- 如果同名 command 和 skill 同时存在，Skill 优先。
- 新项目更推荐使用 `.claude/skills/<skill-name>/SKILL.md`。

## 汇总表

| 场景 | 官方支持语法 | 是否自动展开 / 注入 |
|---|---|---|
| `CLAUDE.md` / `CLAUDE.local.md` 导入文件 | `@README.md` | 是，启动时展开 |
| `.claude/rules/` 自动加载规则 | `.claude/rules/code-style.md` | 是，规则自动加载 |
| `.claude/rules/` 路径匹配规则 | `paths: ["src/**/*.js"]` | 是，匹配文件时生效 |
| Skill supporting files | `template.md` | 否，需要时读取 |
| Skill 注入单行命令输出 | `` !`git diff HEAD` `` | 是，运行时注入 |
| Skill 注入多行命令输出 | ```` ```! ... ``` ```` | 是，运行时注入 |
| Skill 引用当前目录 | `${CLAUDE_SKILL_DIR}` | 用于命令中的路径引用 |
| Subagent 预加载 Skill | `skills: - create-page` | 是，完整 Skill 内容注入 |
| Skill 全量参数 | `$ARGUMENTS` | 是，调用时替换 |
| Skill 位置参数 | `$ARGUMENTS[0]` / `$0` | 是，调用时替换 |
| Skill 命名参数 | `$componentName` | 是，调用时替换 |
| `.claude/commands/*.md` | `.claude/commands/foo.md` | 兼容 Skill 行为 |
