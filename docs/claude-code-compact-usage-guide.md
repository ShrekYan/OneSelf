# Claude Code `/compact` 命令使用指南

> 基于项目实践总结的最佳实践

---

## 📋 什么是 `/compact`？

**上下文压缩命令**，智能总结历史对话：
- ✅ 保留核心信息和关键决策
- ✅ 保留 Agent 对项目的"熟悉感"
- ❌ 去掉冗余的中间步骤、调试垃圾、错误的尝试

```
手动 /compact = 立即触发上下文压缩
自动 Autocompact = 达到阈值后自动压缩
```

---

## 🔄 `/compact` vs `/clear` 本质区别

| 维度 | `/compact` | `/clear` |
|------|-----------|----------|
| 项目记忆 | ✅ 全部保留 | ❌ 全部丢失 |
| 已确认的决策 | ✅ 总结后保留 | ❌ 全部丢失 |
| 中间的弯路、垃圾信息 | ❌ 清理掉 | ❌ 清理掉 |
| Agent 对项目的"熟悉感" | ✅ 保留 | ❌ 重新建立 |
| 操作成本 | 敲一条命令 | 敲一条命令 |

---

## ✅ 什么时候用 `/compact`？

### 场景 1：方案讨论清楚了，准备开始写代码

```
花了 30 条消息把架构方案聊清楚了
↓
进入编码阶段
↓
用 /compact！
```

**效果**：AI 记住了"我们决定用方案 A，不用方案 B 和 C"，但忘掉了讨论过程中那些被否决的想法。写代码时不会再被错误思路干扰。

---

### 场景 2：一个功能写完了，下一个功能和当前项目相关

```
完成了"登录功能"
↓
接下来要做"文章发布功能"（同一个项目）
↓
用 /compact！
```

**效果**：AI 记住了这个项目的所有约定（Prisma 命名、HttpOnly Cookie、页面 5 文件拆分...），但忘掉了"登录功能"的具体实现细节。

---

### 场景 3：讨论绕了弯路，但核心结论是对的

```
一个 Bug 调试了 20 轮，中间走了很多弯路
↓
最终找到了正确的根因和解决方案
↓
用 /compact！
```

**效果**：AI 只记住"最终正确的解决方案"，忘掉了中间 N 次错误的尝试。后续讨论不会再被错误思路带偏。

---

### 场景 4：Token 使用率超过 70%

```
Context Usage 显示 140k/200k (70%+)
↓
Claude 开始"忘记"之前说过的约定
↓
用 /compact！
```

**效果**：一次性释放 30-50% 的 Token 空间，保留所有关键决策。

---

## ❌ 什么时候绝对不要用 `/compact`？

### 1. Token 使用率 < 40%
- 压缩没有任何收益，反而会丢失细节
- 让 Autocompact 自动处理就好

### 2. 正在调试一个复杂问题
- 调试过程中的上下文非常重要
- 压缩可能丢失关键的错误线索

### 3. 对话刚开始（< 20 条消息）
- 内容太少，压缩没有意义

---

## 🔄 什么时候应该继续用 `/clear`？

这些场景 **不要** 用 `/compact`，直接 `/clear`：

| 场景 | 为什么 `/clear` 更好 |
|------|-------------------|
| 方案越聊越乱，AI 明显跑偏了 | 污染的上下文救不回来，不如重来 |
| 下一个任务和当前项目完全无关 | 不需要保留任何项目记忆 |
| 这轮对话质量很低，没什么值得保留的 | 压缩了也是垃圾，不如清掉 |
| 聊了 50 条还没达成共识 | 说明一开始的方向就错了，重置是最优解 |

---

## 🌳 个人决策树

```
当前对话要不要结束？
    ↓
    ├─ 【这轮对话有价值的结论吗？】
    │   ├─ 没有 → /clear ✅
    │   └─ 有 → 进入下一题
    │       ↓
    │       └─ 【下一个任务和当前项目相关吗？】
    │           ├─ 无关 → /clear ✅
    │           └─ 相关 → /compact ✅
    │
    └─ 【还在继续聊吗？】
        ├─ Token < 60% → 什么都不用做 ✅
        └─ Token > 70% → /compact ✅
```

## 💡 高级技巧：配合 `/memory` 使用

**最佳实践组合**：

```bash
# 1. 完成功能，确认决策正确
# 2. 把关键教训添加到项目记忆中
/memory add "Prisma 模型必须用 PascalCase，否则 as any"

# 3. 压缩上下文，Claude 忘掉具体实现，记住核心原则
/compact
```

---

## 📌 一句话总结

> **聊崩了就 `/clear`，聊成了就 `/compact`，聊得好好的啥也不用干。**

90% 的情况用 `/clear` 干净利落，10% 的情况用 `/compact` 选择性保留项目上下文。
