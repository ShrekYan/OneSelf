# Research: 小贝数组工具函数

## Decision: 在前端工具目录新增数组工具入口

**Rationale**: 仓库中已有 `apps/web/src/utils/string.ts` 和 `apps/web/src/utils/number.ts` 分别承载小贝字符串、数字工具函数。数组工具同属前端通用工具能力，放在 `apps/web/src/utils/array.ts` 能保持目录职责一致，并避免影响页面、组件、状态管理、API 或后端服务。

**Alternatives considered**:

- 放入现有 `string.ts` 或 `number.ts`：数组能力与字符串/数字能力混杂，文件职责不清晰。
- 放入共享包：当前需求仅面向小贝前端工具函数，放入跨系统共享包会扩大影响范围。
- 放入页面目录：数组工具是通用能力，不应绑定具体页面。

## Decision: unique 使用基础值身份去重并保持首次出现顺序

**Rationale**: 规格描述为“简单的数组工具函数”，并假设去重面向简单数组。按标准值身份去重可以覆盖常见基础类型数组；保持首次出现顺序符合开发者对去重结果的常见预期，也避免额外排序副作用。

**Alternatives considered**:

- 支持对象深度去重：需要定义深比较规则、性能边界和循环引用处理，超出“简单工具函数”范围。
- 去重后自动排序：会混入排序能力，改变输入顺序语义，不符合单一职责。
- 接收自定义 key 函数：会扩大 API 范围，当前规格未要求。

## Decision: sort 返回升序/默认顺序的新数组

**Rationale**: 规格要求数组排序，并在验收场景中明确数字升序与字符串默认字典顺序。为了避免调用方原数组被意外修改，排序结果应作为新数组返回，保持工具函数纯净、无副作用。

**Alternatives considered**:

- 原地修改输入数组：会产生副作用，调用方可能难以追踪原数组变化。
- 强制只支持数字数组：无法覆盖规格中字符串默认排序的场景。
- 支持自定义比较器：当前规格未要求，会增加接口复杂度。

## Decision: filter 使用调用方提供的布尔条件并返回新数组

**Rationale**: 规格明确 `filter(arr, fn)`，其中 `fn` 是过滤条件。保持条件函数返回布尔值即可覆盖当前需求；返回新数组可避免修改输入，符合纯函数工具定位。

**Alternatives considered**:

- 只支持固定过滤条件：无法满足“调用方指定条件”的核心需求。
- 允许异步过滤条件：会把工具函数变成异步能力，超出简单数组过滤范围。
- 修改原数组并删除不满足项：会产生副作用，不符合工具函数可预测性。

## Decision: 不新增或运行单元测试

**Rationale**: 用户已明确补充“不要添加单元测试”。计划阶段仅保留契约核对、TypeScript 类型检查和 lint 作为验证方式，避免创建与用户要求冲突的测试任务。

**Alternatives considered**:

- 为数组工具新增 Vitest 用例：与用户明确要求冲突。
- 运行现有测试套件：当前需求未要求，且可能被无关测试配置影响。
