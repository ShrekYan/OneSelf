# Stage Specification: 字符串工具

**所属 Feature**: 小贝工具库 (`specs/002-xiaobei-utils`)

**Stage ID**: 01-string-utils

**Priority**: P1

## Overview

本阶段定义字符串工具集合的需求规格，包含 `trim()`、`uppercase()`、`lowercase()` 三个基础字符串处理能力。

## User Story

作为小贝工具库的使用者，我需要一组基础字符串工具，用于清理文本输入、统一大小写展示和标准化字符串处理，从而减少业务代码中重复编写相同字符串处理逻辑。

**Why this priority**: 字符串处理是最基础、最常见的工具能力，也是后续数字工具和数组工具之外最先可独立交付的工具集合。

## Scope

### 包含范围

- `trim()`：去除字符串首尾空格。
- `uppercase()`：将字符串转换为大写。
- `lowercase()`：将字符串转换为小写。
- 所有字符串工具都需要有完整的类型声明。

### 不包含范围

- 不包含除上述三个函数之外的其他字符串处理能力，例如截断、替换、模板格式化、脱敏等。
- 不包含国际化文案转换、语言检测或复杂 Unicode 规范化能力。
- 不包含独立发布为外部工具包的交付范围。

## Acceptance Scenarios

1. **Given** 使用者需要清理首尾包含空格的文本，**When** 使用字符串去空格能力，**Then** 返回结果应去除首尾空格并保留文本中间内容。
2. **Given** 使用者需要统一展示大写文本，**When** 使用字符串转大写能力，**Then** 返回结果应为对应的大写形式。
3. **Given** 使用者需要统一展示小写文本，**When** 使用字符串转小写能力，**Then** 返回结果应为对应的小写形式。
4. **Given** 使用者查看字符串工具定义，**When** 判断工具是否可安全使用，**Then** 每个字符串工具都应具有清晰的输入和输出类型说明。

## Edge Cases

- 当字符串输入为空字符串或仅包含空格时，字符串工具的结果需要保持可预测。
- 当字符串大小写转换遇到非字母字符、数字或符号时，这些字符不应被错误改变。

## Requirements

- **FR-002**: 字符串工具集合 MUST 覆盖 `trim()`、`uppercase()`、`lowercase()` 三个能力。
- **FR-003**: 字符串工具集合 MUST 明确每个能力的输入、输出和行为边界，并提供完整类型声明。

## Success Criteria

- 字符串工具集合仅包含指定的 3 个能力。
- 每个工具函数都具备完整类型声明、清晰输入输出说明和明确行为边界。
- 不包含单元测试交付要求。
