## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 小贝工具库 MUST 作为一个单一 feature 组织字符串、数字和数组三组工具能力，而不是拆分为三个独立 feature。
- **FR-002**: 小贝工具库 MUST 包含字符串工具集合，且该集合 MUST 覆盖 `trim()`、`uppercase()`、`lowercase()` 三个能力。
- **FR-003**: 字符串工具集合 MUST 明确每个能力的输入、输出和行为边界，并提供完整类型声明。
- **FR-004**: 小贝工具库 MUST 包含数字工具集合，且该集合 MUST 覆盖 `add(a, b)`、`multiply(a, b)`、`formatNumber(num)` 三个能力。
- **FR-005**: 数字工具集合 MUST 明确每个能力的输入、输出和行为边界，并提供完整类型声明。
- **FR-006**: 小贝工具库 MUST 包含数组工具集合，且该集合 MUST 覆盖 `unique(arr)`、`sort(arr)`、`filter(arr, fn)` 三个能力。
- **FR-007**: 数组工具集合 MUST 明确每个能力的输入、输出和行为边界，并提供完整类型声明。
- **FR-008**: 小贝工具库 MUST 不包含单元测试交付要求；验收以功能契约、类型声明和行为边界说明为准。
- **FR-009**: 每个工具阶段 MUST 在规格中独立说明包含范围和不包含范围。
- **FR-010**: 每个工具阶段 MUST 有独立的验收标准，并可作为单独能力集合进行评审。
- **FR-011**: 小贝工具库 MUST 保持范围边界清晰，不包含未在三个阶段需求来源中声明的额外工具能力。

### Key Entities

- **小贝工具库**: 一个统一的工具能力集合，包含字符串工具、数字工具和数组工具三个阶段。
- **字符串工具集合**: 面向文本清理和大小写转换的基础工具集合，包含三个指定能力。
- **数字工具集合**: 面向基础数值计算和数字展示的工具集合，包含三个指定能力。
- **数组工具集合**: 面向集合去重、排序和过滤的工具集合，包含三个指定能力。
- **工具函数**: 工具库中的单个可复用能力，具有明确名称、输入、输出、行为边界和类型声明要求。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 使用者可以在一个 feature 规格中找到字符串、数字和数组三个阶段的全部工具需求，而不需要跳转到三个独立 feature。
- **SC-002**: 三个 User Story 均具备独立的包含范围、不包含范围和至少 4 条验收场景。
- **SC-003**: 规格中明确列出 9 个指定工具能力，且没有加入三个阶段来源之外的额外工具能力。
- **SC-004**: 每个工具集合的质量要求都可被评审，包括完整类型声明、清晰输入输出说明和明确行为边界，且不包含单元测试交付要求。
- **SC-005**: 评审者可以根据规格判断每个阶段是否可独立规划、独立验收和独立交付。

## Assumptions

- 该需求是单一"小贝工具库"feature，三个阶段只是同一 feature 下的三个 User Story。
- 目标 feature 目录固定为 `specs/002-xiaobei-utils`。
- 不创建三个独立 feature，也不创建额外外层项目目录。
- 阶段 1 文档中出现的"字符串工具2 / 备份字符串工具函数"视为重复说明，不作为额外第四组工具能力。
- 用户已明确要求"去除单元测试"，因此本 feature 不再把单元测试作为交付或验收要求。
- `formatNumber(num)` 的具体展示格式、`sort(arr)` 的默认排序规则、`unique(arr)` 的去重判定规则将在阶段文档中细化，但本规格限定其必须保持一致且可预测。

## Global Edge Cases

- 当字符串输入为空字符串或仅包含空格时，字符串工具的结果需要保持可预测。
- 当字符串大小写转换遇到非字母字符、数字或符号时，这些字符不应被错误改变。
- 当数字工具接收零、负数或小数时，基础计算能力需要有明确、可预测的结果。
- 当数字格式化接收普通整数、小数或较大数字时，展示格式需要保持一致。
- 当数组为空时，数组工具需要返回可预测结果。
- 当数组包含重复元素、已排序元素、混合顺序元素时，去重和排序规则需要清晰。
- 当数组过滤条件没有匹配项时，过滤结果需要明确为空集合。
